# Архитектура v0.5b Pass 2 (gameplay v0.4b)

Авторитетные деньги, добыча, покупки, бой и quests принадлежат headless Engine. Phaser/UI отображают state и вызывают команды. Игровые числовые параметры принадлежат JSON обоих профилей; размеры спрайтов, pivots, frames и декоративные placements находятся в game/art и BayScene. Правила дохода не дублируются в UI.

## Системы

- state: v3, прежние boats/nodes/cargo/orders/combat + coinStacks с source и provenance, revealedPurchases, golden.offerId/transaction. CoinStack имя сохранено для совместимости, новые записи — одна выплата за единицу товара.
- engine: шаг ≤1/30с, timers/resources → traffic begin/separation → движение player → pickup/harvest/deposit → workers → idle parking → collect/purchase → combat/merchant → traffic end → quests/reveals. controlsLocks — transient Set; только modal блокирует движение и платежи. CameraGuidance не ставит input lock. Таймеры, workers и combat продолжаются; camera controller не меняет позицию лодки. Обычные события боя (например respawn) сохраняют своё действие.
- construction: allOffers для debug, offers фильтрует data-driven раскрытие. Reveal threshold относится к категории (cargo/worker/salvage) или отдельному resource. Progress, existing orders и owned state сохраняют доступ. revealPurchases фиксирует открытие. Visibility: HIDDEN / AVAILABLE / PARTIALLY_PAID / BUILDING / READY. WeakMap хранит предыдущую позицию, ближайший offer и непрерывную остановку. Engine передаёт max(фактическая скорость после collision/world clamp, запрошенная скорость управления). Поэтому input в заблокированную сторону не запускает платёж. Оплата учитывает только часть dt после задержки; один ближайший offer, фиксированные cost/metalCost и cumulative integer pour targets. Два временных clock в WeakMap<Order> удерживают sub-coin время между кадрами, без дробных новых взносов. Продолжительность min+(max-min)*cost/(cost+cost_scale); target=floor(cost*(elapsed/duration)^ease). Независимые coins/metal clocks после нехватки средств возвращаются к фактически paid fraction. Полная цена закрывается точно; после движения/reload остаток продолжается по оплаченному прогрессу. Persistent purchaseGuards хранят cooldownUntil и needsExit по категории точки, а не order ID. Guard ставится при order_paid и timer_finish, включая Skip/offline finish. Только реальный выход за purchase_radius+exit_hysteresis сбрасывает needsExit; cooldown не заменяет exit/re-entry. Первый заказ без guard работает сразу. Engine.purchase — явная headless/debug команда полного платежа, игровой UI её не использует; bypass physical gating здесь намеренный для debug/funded fixtures.
- economy: один delivery удаляет ровно один Cargo и создаёт одну fish_sale CoinStack того же value. availableAt фиксирован один раз, новые deliveries не откладывают старые монеты. Контролируемые water positions; collection за один проход формирует remaining array. Только player собирает деньги. creditIncome — единый классификатор fish_sale / golden_reward / quest_reward / debug_grant. total_earned_coins включает все четыре; earn_coins — только fish и golden при collection. fish_sales_earned, golden_bonus_income, quest_reward_income, debug_income хранят источники отдельно; golden_collected оставлен как совместимый alias. Actual rate остаётся fish-only. Существующие общие «Заработать» цели используют earn_coins; fish_sales_earned condition type сохранён для будущих sale-only задач. Metal поступает только в свой открытый warehouse и сохраняет cargo при полном складе.
- guidance: questOfferId и questFocusTarget — общий resolver UI/headless; fallback к порту, water/world bounds. nextQuestHintTarget разрешает показ только существующей active задачи после claimQuest → activateQuest → updateQuests; completed_unclaimed требует отдельного claim и не запускает повторную подсказку. CameraGuidance работает по wall-clock dt с smooth interpolation FOLLOW_PLAYER → FOCUS_TARGET → RETURN_TO_PLAYER. Keyboard/joystick/navigation не отменяют показ и не сбрасывают его таймер. Return следует за текущим положением движущегося игрока. Повторный hint заменяет прежний, конкурирующих camera tweens нет. На hidden/shutdown hint отменяется. Камера и стрелка не сериализуются.
- merchant/engine: golden movement и lifetime сохранены. offer snapshot → offered → watching → spawned либо cancelled. begin проверяет lifetime и ID. После принятия fake ad watching защищает обещанную награду от normal expiry. Confirm создаёт 10 целых payouts с остатком, ID и source; wallet не меняется до collect. Повторный confirm отвергается. Отмена не выдаёт деньги. Новая лодка получает новый offerId.
- save: v1/v2 → v3 в прежних profile keys, nested validation, exact backups перед принятием миграции. Несобранные v2 stacks сохраняются как fish_sale, не делятся выдуманным способом. Старые completed/partial purchases фиксируют reveal. Новые ID выше всех сохранённых ID. watching при reload становится offered: браузер не может доказать завершение прерванного ad. Координаты старых лодок/монет корректируются на воду текущей геометрии без reset progress. Invalid save не перезаписывается.
- resources/workers/combat/movement/timing: сохраняют v0.2 HP/stock/regrow/restock, separate active catches/pickups, 65/35 выбора ресурса, crate preemption/reservations/resume, патруль и travel projectiles, visibility graph/coast correction, FrameClock и offline timers. Лодки друг с другом не сталкиваются.
- BayScene + game/art/registry + sceneAssembly: approved PNG rendering обеих зон; preload общих sheets/images, 8-way frames всех 7 типов boats с малым presentation roll без изменения directional frame. Runtime sheets 192×192 нормализованы по alpha area, исправляют compass order Golden/Salvage/Guard; Golden heading выводится из фактического frame displacement и сохраняется при остановке, без записи в Engine/save. Resource stage по общему stock+portion HP, все 9 resource types; crate images по Cargo.id, размер 36/42/36, per-direction deck offsets. Вода — stationary TileSprite с mirror-repeat утверждённого original и общими UV по всей карте. sceneAssembly хранит только декоративные PNG placements, заменяет все острова/zone-2 buildings, не добавляет colliders или input handlers. Zone-2 images видимы по area. Mooring guides не меняют gameplay points. Resource name/recovery только кратко; подпись может перейти выше source при проходе лодки снизу. Compact price/name, progress ring и отдельный finger-size SKIP. Coin image+text pairs переиспользуются, вне камеры не создаются, max_coin_views ограничивает только отображение. max_live_effects ограничивает существующие transient анимации, не выплаты. Данные монет не удаляются ради лимита. Renderer metadata/maps не сериализуются. Актуальная подготовка PNG: scripts/prepare-art-v05b.py; v05a builder остаётся историческим и не предназначен для current sheets. Подробности: ART_INTEGRATION_V05B_PASS2.md.
- UI: компактная full-card quest, modal choice перед fake ad, Golden popup по tap, input locks, debug/export. Confirm/claim немедленно вызывает persist. UI purchases только задают путь. Keyboard repeat не выдаёт последовательность наград.

## Денежные инварианты и события

1. Cargo → physical payout → wallet; баланс изменяется только при collection. Каждый payout ID коллекционируется единожды, удаляется из pending в том же state update.
2. Всегда `pending sum + collected sum = issued sum`; рендер может скрывать отдельные выплаты, экономика не объединяет их. Сохранение атомарно включает wallet и pending.
3. Золотая транзакция и кучки сохраняются вместе. Spawned сохраняет 10 issued IDs, включая собранные; pending содержит только неполученные. Четыре собранных → после reload шесть pending.
4. Claim current quest ID, rewarded IDs и completed_unclaimed сохраняют lifetime/since_activation. Каждая уже выполненная следующая цель требует отдельного claim.
5. Новые события: golden_offer {id,offerId,coins}, golden_reward_started {id,offerId,coins}, golden_reward_cancelled {id}; reward {source:golden,coins,transaction,delivery:physical}. coin_spawn {id,value,source,crate?,boat?,transaction?,x,y,fromX,fromY}; coin_collect {id,value,source,crate?,boat?,transaction?,x,y}. Старые delivery/purchase_payment/timer/reward/quest events сохраняются. Старые coin_collect без source в actual rate трактуются как продажи. CSV/JSON экспорт сохраняет эти поля в data.

## Экономическая модель

EstimatedEarnRate и banker rounding сохранены: max potential fish yield лодки с учётом travel, gather/unload, resource availability и utilization; metal/defender исключены. Новые расстояния меняют travel input и golden estimate. Цены, номиналы, rewards, скорости лодок, бой, HP/stock и timers не перебалансированы. Новый pickup radius и stationary delay меняют фактический pacing. Требуется повторное ручное измерение обеих партий; scripted sanity — только достижимость.

## Совместимые поля v0.3.1

Version=3 и save keys сохраняются. `income_sources_v031` и наличие purchaseGuards позволяют выполнить feature migration один раз после валидации, предварительно сохранив raw backup_before_v031. Historical earn=fish_sales_earned+golden_collected; active since_activation income baseline += historical golden, чтобы сохранить прежний progress. Quest reward income восстанавливается из rewarded IDs; старые debug grants достоверно восстановить нельзя, debug_income начинается с нуля и total отражает известные источники. Wallet при этом не меняется. Старые частично paid дроби возвращаются в тот же wallet: wallet+paid сохраняется; epsilon нормализует только почти целый wallet. Новые заказы целочисленны, редкий произвольный дробный legacy wallet остаток не стирается.

Guard legacy completed/owned categories требует выхода, поэтому новая цена на том же причале не оплачивается сразу после reload. Partial order продолжается после новой остановки; ранее завершённая покупка всё равно защищает свою категорию. Временные pour clocks, joystick capture/vector и camera state не сериализуются.

`FloatingCrate.expiresAt` сохраняет deadline в game time, поэтому offline timers тоже удаляют просроченные ящики без денег. Старые ящики получают один deadline при первом load; их координаты корректируются на воду. `nextId` проверяется по cargo/crates/coins/transaction. Spawn допускает min(drop_crates, max-current) и пропускает overflow: без eviction, очереди, подмены номиналов или deferred duplicates. Legacy >150 сохраняются, новые drops блокируются до освобождения мест. Expiry удаляет reservation вместе с ящиком; прежний Worker AI сам освобождает target и возобновляет ловлю.

## Управление и placeholder-причалы

UI.Joystick слушает PointerEvent на canvas и появляется под мышью/пальцем только на свободной воде. BayScene.canStartJoystick преобразует CSS координаты в Phaser screen/world и проверяет Phaser hitTestPointer, землю, границы, Golden hull и физические purchase circles. DOM UI получает собственные события. Canvas захватывает первый допустимый pointer, фиксирует центр в CSS координатах первоначального нажатия и преобразует отклонение в нормализованный вектор; magnitude после deadzone переотображается в 0..1. DOM-круг и thumb — только визуальный overlay с pointer-events:none, скрытый вне удержания. Второй палец может нажать quest/UI или Phaser SKIP/Golden, не забирая capture; открытие modal завершает управление. pointerup/cancel/lostpointercapture, blur, hidden и modal сбрасывают vector/thumb/capture; shutdown также удаляет слушатели джойстика. Keyboard reset и waypoint cancel предотвращают скрытое автодвижение. При одновременно активной клавиатуре её вектор имеет приоритет. Обычный mouse/touch click по воде не включает navigation; taps Golden/покупки/SKIP и кнопки навигации сохраняют отдельные команды. Phaser clamps итоговую длину, поэтому диагональ не ускоряет лодку.

`docks` хранит береговой anchor, end, width, equipment и zone. BayScene рисует заменяемые деревянные/патрульные причалы с оборудованием. Покупки остаются на воде за концами причалов. Painted pontoons не добавляют коллизию; существующая island/rock геометрия и visibility graph сохранены. Ресурсы выбрасывают crates через waterLootPoint с уникальными точками и water reachability; короткие crate_spawn/resource_depleted эффекты ограничены прежним max_live_effects. Один crate ID имеет один визуальный объект: во время flight статичная копия скрыта, при collection/expiry tween удаляется.

## Навигация и traffic v0.4b

`movement.ts` сохраняет visibility graph, world clamp и острова/скалы с padding=16. WeakMap motion handlers связывают `navigateTo` и ручной input с `traffic.ts` только во время simulation step. Projectile `moveTo` остаётся независимым. Grid 110px переиспользует buckets; соседние hulls собираются один раз на движение, candidate point и handler переиспользуются. Предсказание скорости использует предыдущий dt, включая переменный renderer FPS.

Traffic включает player/worker/speedboat/salvage/defender/pirate; Golden остаётся декоративным. Номинальная оболочка мягкая, swept core = 90% суммы радиусов. Player pinned при нулевом input, workers уступают его реальной аналоговой скорости. Пересечения из сохранения постепенно расходятся; коррекция NPC ограничена 36px/s и проверяет воду/сегмент/границы. Нет новой emergency телепортации. Старые combat respawns сохранены; после перемещения сбрасывается только runtime prediction/route history.

Runtime arrival places: hex grid внутри radius=78 для ресурса; кольцо radius=36 и FIFO для порта/склада. Освобождённое, ещё занятое уходящей лодкой место получает штраф при следующем назначении. Рабочий остаётся на назначенной позиции, пока меняется только маршрут, и начинает/продолжает работу исключительно внутри реальных radii. Пустой WAIT возле порта отходит на стоянку после Worker AI, сохраняя приоритет crates. Общий travel budget не позволяет parking и выбору новой цели удвоить движение за шаг. Crate reservations принадлежит прежнему Worker AI.

Pirates получают свободный water spawn и разные подходы к общему home; сам chase anchor и target selection неизменны. Attack radius, cooldown, HP, damage и repair/spawn clocks прежние. Декоративные docks не превращены в новые препятствия. Runtime grid/routes/arrival queues/velocity/stuck/metrics не сериализуются; state.version=3 и profile save keys прежние. [Параметры, throughput и компромиссы](NAVIGATION_V04B.md), [доказательства и ручные проверки](VALIDATION_V04B.md).


## Presentation v0.5c

`game/art/animation.ts` хранит только visual config (четыре cargo anchor tables находятся в registry), ambient helpers и critically damped spring. `VisualEffects.ts` использует единый Graphics, fixed particle slots и shared Image/Text pools. `BayScene` связывает transient effect maps с уже выполненными engine events; VFX callbacks не мутируют engine. Flights следуют за текущей палубой, crate burst перемещает только существующее изображение, coin pop не меняет физический payout.

Harvest/pickup получают origin x/y, delivery resource, pirate_killed coordinates/angle; combat_attack/combat_hit — новые diagnostic/presentation events, без новых боевых правил. Новый event log не используется для управления AI. Начальный seq исключает повторение исторических событий при загрузке; state replacement/shutdown очищает все transient объекты. Save version=3, keys и оба economic JSON прежние. Defender purchase=(2250,1220) сохранён; изменено только artwork station=(2290,1060), 203×221. Gate artwork=143×169. Прежние описания transient tweens/crateFlights в исторических разделах заменены новым VisualEffects layer. [Параметры, anchor table, лимиты](ANIMATION_V05C.md), [проверки](VFX_VALIDATION_V05C.md).
