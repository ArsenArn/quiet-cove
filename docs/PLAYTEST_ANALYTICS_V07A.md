# Playtest Analytics v0.7a

Локальная аналитика — наблюдатель существующего `debug/events.log`, а не игровая механика. По умолчанию OFF. Данные не отправляются на сервер; баланс, save schema, награды, AI, cargo, навигация и таймеры не менялись.

## Как записать прохождение

1. Выберите FAST в F2 / Balance Lab (смена профиля доступна при разрешённом debug override).
2. Начните New Game кнопкой Reset с подтверждением.
3. Сразу откройте F2; в верхней части панели есть **PLAYTEST ANALYTICS**.
4. Нажмите **Start Recording**. Если осталась предыдущая запись, сначала экспортируйте её и подтвердите **Clear Recording**.
5. Закройте F2 и играйте обычным образом, без грантов и ускорения времени.
6. Нажмите **Stop Recording**, затем **Export JSON**. Отправьте скачанный `playtest_FAST_<UTC-date>_<session-id>.json` для анализа.

Те же кнопки доступны через Settings → Balance Lab. Они переводятся при смене EN/RU, используя существующий выбранный язык. Start не начинает новую игру и не изменяет игровой save. Можно начать посреди партии: текущее состояние становится baseline, `recording_started_midgame=true`. Неизвестные исторические времена не восстанавливаются искусственно.

Export работает во время записи, не останавливает её и не очищает данные. Повторный экспорт возвращает всю текущую сессию. Stop сохраняет запись и фиксирует конечное состояние: дальнейшая игра не изменяет экспорт. Clear требует подтверждения и затрагивает только аналитику. Чтобы создать следующую сессию, сначала экспортируйте/очистите предыдущую; Start не перезаписывает её автоматически.

New Game завершает текущую запись с причиной `new_game`. Она остаётся доступной для экспорта, а новая запись начинается только по Start. Смена FAST/REFERENCE завершает запись с `profile_switch`; профильные записи изолированы.

## Что измеряется

- Все 34 квеста: activation, completion, manual claim, длительность и задержка получения награды. Уже выполненный при активации квест может иметь duration=0. Если completion произошёл до Start, его время и длительность — null.
- Доход: `fish_sale`, `golden_reward`, `quest_reward`, `debug_grant`, резервный `other`. Доставка/создание монет не являются доходом: он возникает при фактическом подборе.
- Инвестиции: точные взносы coins/metal, partial/full payment, начало/окончание стройки, длительность ожидания и actual skip type. Время до полной оплаты отделено от строительного таймера.
- Ресурсы: получение/доставка по видам, игрок/рабочие, collected/expired floating crates, depletion/recovery, фактически собранный доход по ресурсу и лодке. Происхождение давно созданных baseline-монет может быть `baseline_unknown`.
- Флот: обычные, скоростные, salvage workers и defender; завершение создания, стоимость, вместимость и текущий этап. Для работников учитываются resources, deliveries и собранные coins.
- Прогресс: revealed offers, построенные ресурсные зоны, оплаченная/построенная территория, первое фактическое пересечение границы зоны 2, defender, склад, cutter и scrap.
- Golden: offer shown/accepted/declined/expired, отмена принятой награды, fake ad start/complete/cancel, spawned и collected coins отдельно. Construction ads связаны с purchase ID, Golden ads — с transaction ID.
- Бой: pirate kills, destruction/respawn игрока и защитника. Частые попадания по игроку агрегируются как `player_damage` и `player_damaged_count` в интервалах.

Snapshots сохраняются каждые 30 **активных** секунд, при квестах, полной оплате/завершении стройки, открытии ресурса/территории, важных debug-действиях и Stop. Они содержат деньги, pending по источникам, металл, флот, текущие инвестиции, груз по ресурсам, stock/HP/phase/readyAt ресурсов и session production totals. Последние 30/60 секунд продаж считаются в active-time окне и только по фактически собранным fish-sale монетам.

Все агрегаты — изменения **после Start**, а не lifetime statistics игрового save. Начальные деньги, металл, груз, pending и инвестиции находятся в initial snapshot. Доход рабочего означает его доставленную рыбу, чьи монеты затем собрал игрок; доставка сама по себе ещё не дала кошельку деньги.

## Время и восстановление

`wall` — реальное время от Start, включая фон и закрытую страницу. `active` — время видимой/сфокусированной страницы с доступным управлением и непоставленной на паузу симуляцией. `game` — положительное продвижение `state.time`; ускорение и offline timers отражаются здесь отдельно от active.

visibilitychange, blur/focus и pagehide/pageshow создают pause/resume. Фон не увеличивает active. При reload весь промежуток между последним checkpoint и восстановлением считается wall-only. Уже учтённое active время не начисляется повторно; собственные event IDs продолжаются. `offline_progression` отмечает существующую политику игры: offline продвигает только таймеры, без ловли, продаж или боя.

Доступность управления/программная pause проверяются с периодом 200мс; границы visibility фиксируются сразу. Поэтому короткие modal/lock переходы могут иметь погрешность до одного периода опроса. Wall clock монотонно ограничивается при переводе системных часов назад. Закрытая страница не приносит active время.

Игровой save и аналитика независимы. При штатном сохранении game save пишется первым. После аварийного завершения их checkpoints могут расходиться: в таком случае записывается `restoration_adjustment` по кошельку/металлу. Это явная корректировка сверки, а не выдуманный доход. Детали операций в аварийно несохранённом хвосте восстановить гарантированно нельзя. Запись не воспроизводит старые gameplay events и не выдаёт награды.

## Debug contamination

Grant Coins, Grant Metal, quest jump, Open Zones, speed change, config edit и любое событие `debug_*` порождают `DEBUG_ACTION`. В экспорт входят параметры, before/delta при наличии и состояние после действия; `debug_modified=true`. Изменения runtime config сохраняются отдельными `balance_configuration_changed` с полным загруженным config и новым fingerprint.

Исторические debug events, ещё присутствующие в игровом журнале при Start, и уже включённое ускорение также делают baseline contaminated. Старые вычищенные из ring buffer debug-действия достоверно определить нельзя. Открытие F2, Start/Stop/Export и просмотр диагностик не загрязняют сессию.

Изменение speed вне UI также обнаруживается при очередном sample. После reload возврат runtime speed/config к загруженным значениям явно отражается в экспортируемых событиях, чтобы прежний override не считался продолжающим действовать.

## Хранение, объём и нагрузка

Основное хранилище — IndexedDB `quiet_cove_playtest_analytics`, store `recordings`, ключ `quiet_cove_analytics_v1_<profile>`. Запись имеет синхронный memory mirror; асинхронные транзакции выполняются по порядку. При недоступном IndexedDB применяется отдельный localStorage analytics key. Обычные игровые ключи `quiet_cove_fast_v1` / `quiet_cove_reference_v1` и schema=3 сохранены.

Flush — раз в 5 wall секунд, а также при pause, persist, export и stop; gameplay не ждёт успешного flush. Повторяющиеся harvest/delivery/pickup/payment/combat операции объединяются в интервалы примерно по 5 active секунд, с дополнительными границами важных событий. В JSON не попадает каждое движение лодки/каждый кадр.

Лимит checkpoint: 20 000 000 bytes для IndexedDB, 3 000 000 для fallback localStorage, консервативная оценка `JSON.length*2`. Дополнительно: 12 000 event records или 1 000 snapshots. При лимите запись автоматически STOPPED с `storage_limit`, остаётся доступной для экспорта, и показывается предупреждение; журнал не обрезается тайно. Окончательный stop record может дать небольшое превышение порога. Pretty-printed экспорт больше компактного checkpoint.

При quota/write errors игра продолжает работать, запись остаётся в памяти, панель показывает предупреждение. Экспортируйте до закрытия. Асинхронный последний flush может не успеть при аварийном закрытии браузера; обычный reload проверен в браузере. Хранилище привязано к origin: смена порта/домена не переносит запись. При OFF журнал аналитики и snapshots не строятся и не сериализуются.

Worker idle time не измеряется: надёжного authoritative счётчика нет. OS alt-tab, физические телефоны, crash durability и естественный pacing человека требуют ручного playtest. Scripted 34-chain — доказательство полноты экспорта и сверки, а не измерение человеческого времени 5–10 минут.
